# WebRTC Camera Link

AndroidとiPadの両方で同じGitHub Pages PWAを使う、個人用のカメラ・マイク共有試作です。

## 構成

- Android：ChromeでPWAを開き「ホーム画面に追加」→「Android：配信する」
- iPad：SafariでPWAを開き「ホーム画面に追加」→「iPad：受信する」
- シグナリング：PeerJS Cloud（PeerJSの公開シグナリングサービス）
- メディア：WebRTCで端末間を直接接続
- ホスティング：GitHub Pages
- GAS：不使用
- Android APK：不使用

映像・音声をGitHubへアップロードしたり保存したりしません。GitHub Pagesはアプリの配信に使い、PeerJS Cloudは接続開始に必要な情報の交換だけに使います。ネットワーク環境によってはTURNサーバーが必要です。

## 公開

1. Settings → Pages → Build and deployment → Sourceを「GitHub Actions」にします。
2. `docs/` の変更がmainへ反映されるとPagesワークフローが公開します。
3. 公開URL： https://a09848281-prog.github.io/android-ipad-peerjs-rtc/

## 使い方

1. AndroidとiPadで上記URLをHTTPSで開きます。
2. iPadで「ホーム画面に追加」し、ホーム画面のアイコンから起動します。
3. iPad側で「iPad：受信する」→「受信IDを発行」を押し、表示されたIDをコピーします。
4. Androidで「ホーム画面に追加」し、ホーム画面のアイコンから起動します。
5. Android側で「Android：配信する」を選び、iPadの受信IDを入力します。
6. 「カメラ・マイクを開始して送信」を押し、カメラ・マイクの権限を許可します。
7. iPadで映像・音声が届いたことを確認します。
8. 終了時はAndroid側の「配信を停止」、iPad側の「切断」を押します。

## Androidの画面ロックについて（重要）

AndroidのPWA・ブラウザでは、画面ロック、別アプリへの切り替え、省電力制御、ブラウザによるページ停止などでカメラ・マイクやWebRTC通信が止まることがあります。Webページだけで画面オフ中の継続取得を保証することはできません。Galaxy A22 / Android 13実機での検証が必要です。安定運用では配信中にページを前面表示し、画面を点灯したままにしてください。

ロック画面から遠隔操作でカメラ・マイクを新しく起動したり、OSの許可・通知・プライバシー制限を回避したりすることはできません。

## 接続・プライバシー上の注意

- iPadの受信IDを知っている人は接続を試せるため、IDを不特定多数へ公開しないでください。
- PeerJS Cloudは第三者のシグナリングサービスです。サービスの稼働・利用条件に依存します。
- WebRTCは通常P2Pですが、NATやネットワーク制限により直接接続できず、TURN中継が必要な場合があります。
- PeerJS CloudやGitHub Pagesの利用可能性・仕様変更により動作が変わる可能性があります。
- この変更はコード上の構成変更であり、Galaxy A22とiPadでの実機動作確認済みという意味ではありません。

## トラブルシューティング

- カメラが使えない：HTTPSで開いているか、ブラウザのカメラ・マイク権限を確認してください。
- 受信IDが発行されない：ネット接続とPeerJS Cloudへのアクセスを確認してください。
- 接続できない：iPad側が受信待機中か、IDが正確か確認してください。
- 接続するが映像が出ない：両端末のネットワーク制限を確認してください。TURNが必要な場合があります。
- 画面ロック後に停止する：PWAの制約です。Webだけでは継続を保証できません。
